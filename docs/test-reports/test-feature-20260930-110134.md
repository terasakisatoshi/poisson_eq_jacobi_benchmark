## Per-Feature Details

### Python/Numba setup and execution

- **Role:** New downstream user familiar with command-line tools and Python, but not this repository.
- **Use Case:** Follow the README to create the uv environment and run the Python solver.
- **What they tried:** `uv sync --project python` followed by `uv run --project python python/poisson.py`.
- **Discoverability:** The README clearly identifies the `python/` directory, uv commands, and the Python entry point.
- **Setup:** The documented setup succeeded. uv resolved and installed `numba`, `numpy`, and `llvmlite`.
- **Functionality:** The solver completed successfully and printed time, 100,000 iterations, final update error, maximum error, and L2 error.
- **Expected vs Actual Outcome:** Matched. The Python output used the same error values as the other implementations.
- **Blocked steps:** None.
- **Friction points:** The README does not state how to install uv or the supported Python version. It also does not explicitly say that commands are run from the repository root.
- **Doc suggestions:** Add a prerequisites section with uv/Python requirements and a sentence stating the working directory.

### All-language benchmark result generation

- **Role:** Same downstream user, now trying to reproduce the comparison table.
- **Use Case:** Run `./benchmark/run.sh` and inspect `benchmark/RESULT.md`.
- **What they tried:** The documented benchmark command from the repository root.
- **Discoverability:** The command and output path are clearly documented.
- **Setup:** The command succeeded in this environment.
- **Functionality:** All five current implementations (Julia, Python + Numba, C++23, Fortran 2008, and Rust) ran; `benchmark/RESULT.md` was regenerated with timing, device, iteration, and error columns.
- **Expected vs Actual Outcome:** Matched. The result file was populated successfully.
- **Blocked steps:** None; all required toolchains were already available.
- **Friction points:** The README calls this an all-language benchmark but does not list the required Julia, uv/Python, C++23, gfortran, and Cargo toolchains together. It does not explain that the Python run includes a Numba warm-up or show expected output/failure guidance.
- **Doc suggestions:** Add an explicit prerequisite list, distinguish Python-only execution from the all-language benchmark, and mention the JIT warm-up and generated result location.

## Expected vs Actual Outcome

The expected outcome was achieved. The documented uv setup and benchmark command produced a valid `benchmark/RESULT.md`. The only findings are documentation improvements around prerequisites and reproducibility guidance; no functional blocker was found.

## Issues Found

1. **Medium:** README lacks a consolidated prerequisite list for the all-language benchmark.
2. **Low:** README does not specify uv installation or Python version requirements.
3. **Low:** README does not explicitly state the repository-root working directory or describe Numba's first-run JIT warm-up.

## Blind-Mode Findings

**Doc surface provided to the blind tester:** `/tmp/poisson-docs.uhOMsy/README.md` (a copy of the repository `README.md` only).

The blind tester could identify the Python setup commands and benchmark output path without source access. The orchestrator then verified the commands against the real project:

```text
uv sync --project python
./benchmark/run.sh
```

Both commands completed successfully; the benchmark reported successful runs for Julia, Python, C++23, Fortran 2008, and Rust and saved `benchmark/RESULT.md`.

## Suggestions

- Add a `Prerequisites` section covering uv, Python, Julia, a C++23 compiler, gfortran, and Cargo.
- State that all commands are run from the repository root.
- Keep the Python-only command separate from the all-language benchmark command.
- Mention that Numba performs a small warm-up/JIT compilation before the timed solve.
